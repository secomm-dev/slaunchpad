## Responsive/static review

- Mobile 8px, Tablet 32px and Desktop 40px gutters are implemented from the
  canonical master components.
- Browser viewport verification confirms 8px at 375px and 32px at 640px; the
  Tablet breakpoint is intentionally `sm` rather than Tailwind `md`.
- Mobile/Tablet action order is Menu + Logo / Search + Account + Cart; Wishlist
  is Desktop-only.
- Browser viewport measurements:
  - 375px: Header 64px, 8px gutters, Wishlist hidden, zero horizontal overflow.
  - 640px: Header 64px, 32px gutters, 16px action gap, zero overflow.
  - 1440px: 40px gutters, equal flexible side columns around the fixed 120px
    logo slot with 24px column gaps, 118×18 rendered logo, zero overflow.
- Header action geometry was revalidated against Figma nodes `2151:9517` and
  `2115:5849`: Desktop Utility Navigation uses a 24px gap, Tablet Shortcut uses
  16px and Mobile Shortcut uses 8px. Search, Account, Wishlist and Cart render
  as 40×40 action areas with 8px padding around exact 24×24 custom SVGs.
- Header actions reuse the Global Style `btn` + `btn-transparent` foundation
  without a `btn-size-*` modifier. Header-local Tailwind custom-property
  utilities preserve contextual `currentColor` and the Figma 24px glyph size;
  hover, focus, active and disabled states remain owned by the global
  `btn-transparent` variant.
- The custom language trigger clears focus after pointer activation and applies
  `outline-none` in every state, per the approved visual decision. This is a
  documented accessibility deviation because keyboard focus no longer has a
  visible indicator on this trigger.
- Homepage is transparent/white at scroll top and changes to the full-width
  solid sticky treatment at scroll; non-home pages start solid.
- Hyvä's `header.container` remains the single semantic `<header>` landmark;
  the Header template renders a child `<div>` rather than nesting landmarks.
- Homepage overlay positioning is owned by the outer page Header: `fixed` when
  sticky is enabled and `absolute` when disabled. No negative-margin layout
  compensation is used; non-home pages retain in-flow `sticky` positioning.
- A visible Magento global message supplies a runtime Header offset: the fixed
  Homepage Header remains directly below the message until it scrolls out, then
  settles at `top: 0`. The implementation measures the rendered message instead
  of hard-coding its height and keeps the no-message path at zero offset.
- Local static deployment required clearing only the generated Launchpad paths
  in `pub/static` and `var/view_preprocessed`; source CSS build alone was correct.
