## 1. Approach

Build a one-way deterministic pipeline:

```text
immutable Figma export
  → audit + production contract
  → theme-owned transformer
  → generated Figma token CSS
  → Tailwind v4 / Hyvä semantic hooks
  → source-owned global foundation styles
  → on-demand Figma SVG audit + Hyvä icon assets
  → build + browser evidence
```

The transformer keeps source tokens under `--ds-*`, preserves brand aliases and
publishes only approved semantic APIs. It does not replace Hyvä's own
`hyva-source.css`/`hyva-tokens.css` generation. Source CSS remains responsible
for document defaults, fonts, container, focus, Button and Form hooks.

Rejected approaches:

- Editing export/generated CSS manually — not reproducible.
- Generating utilities for all primitives — unstable public API and CSS bloat.
- Flattening Olive values into semantic tokens — prevents child brand override.
- Shipping dark mode because it exists in export — not production-approved.
- Adding `tailwind.config.js` — incompatible with the project's CSS-first contract.

## 3. Ordered implementation phases

### Phase A — Contract and audit hardening

1. Create theme-owned `tokens/contract.yaml` from approved input.
   - Allow: light, olive, Inter, Mobile/Tablet/Desktop, applications Button tokens.
   - Exclude: dark runtime, CTA zero modes and raw documentation palettes.
   - Verify: contract schema validation and explicit no-default fallbacks.

2. Adapt the bundled transformer into `web/tailwind/scripts/`.
   - Preserve ID-based aliases when possible.
   - When native export target ID is unavailable, resolve by exact target
     collection + token path; require one unambiguous match.
   - Keep normalized-name collisions and unresolved production aliases fatal.
   - Normalize output identifiers only; do not mutate source casing.
   - Verify: fixture/unit-style CLI checks for ID, name fallback, ambiguity,
     missing target, casing collision and suspicious zeros.

3. Add explicit npm scripts and generation order.
   - `tokens:audit` writes report only when explicitly invoked.
   - `tokens:generate` writes generated CSS.
   - `generate` runs token generation plus `hyva-sources` and `hyva-tokens`.
   - Verify: build/watch do not rely on lifecycle hooks or skill paths.

### Phase B — Generated token layers

4. Generate source variables, default light semantics and Olive brand layer.
   - Preserve semantic brand aliases as references.
   - Do not emit dark runtime CSS.
   - Combine effect geometry and mode-aware effect colors.
   - Verify representative primary/text/border/status/focus aliases.

5. Publish only approved Tailwind namespaces.
   - Reuse framework spacing/breakpoints when identical.
   - Add semantic typography/radius/shadow/color names only when stable.
   - Do not expose all primitives as utilities.
   - Verify expected utilities compile and unapproved raw utilities do not.

### Phase C — Source-owned global foundation

6. Add Inter assets and font loading.
   - Download approved static WOFF2 latin/vietnamese faces for normal/italic,
     weights 400/500/600/700, plus license.
   - Declare `font-display: swap`; preload only measured critical normal face.
   - Verify response paths, computed font family/weight/style and no 404/CORS.

7. Map document and typography defaults.
   - Body, headings, labels and semantic type APIs consume generated variables.
   - Mobile base, Tablet at 768px, Desktop at 1280px.
   - Verify Vietnamese diacritics, English expansion and 320px reflow.

8. Replace wrapper with approved container contract.
   - Preserve Hyvä max-width rules below 80rem and from 96rem; use 8px mobile and
     24px tablet/desktop padding; override only 80rem–95.999rem to outer 1408px.
   - Keep full-bleed shell and documented component exceptions possible.
   - Verify 375/768/1024/1440/1920 measurements.

9. Map focus, links, status and reduced motion.
   - Reuse `--outline-*` and semantic interaction/effect tokens.
   - Keep keyboard-visible focus and native semantics.
   - Verify contrast and `prefers-reduced-motion: reduce` behavior.

### Phase D — Button and Form foundation

10. Apply the approved Button decisions before code.
    - Q-010: treat Button page `2410:25885` as the parent inventory; use current Button `2410:25972` and Base Button `2410:26973`; exclude Legacy Button `2410:25890` and Legacy Icon Button `2410:25923`.
    - Q-011: implement all five master sizes; reuse exported values only where exact and do not invent a one-to-one mode-name mapping.
    - Q-012: preserve 32/36/40px visual controls with a minimum 44×44px interaction area.
    - Verify decisions are recorded in spec/input.

11. Implement Button hooks/API.
    - Primary/secondary/tertiary/transparent; default/hover/active/focus-visible/disabled.
    - Text, leading/trailing icon, icon-only and round icon-only structures.
    - No loading/full-width global variant unless scope changes.
    - Verify native `<button>`/`<a>` semantics and keyboard behavior.

12. Implement the approved Form foundation.
    - Audit `2410:14473`, `2410:14352`, `2410:15699` and `2410:15674`; exclude
      the two Legacy sets.
    - Normalize the large Figma permutation matrix into semantic native-control
      hooks: field, label, hint/validation message, addon/icon slots, state and
      feedback. Do not emit one CSS API per permutation.
    - Map Placeholder/Hover/Active/Filled/Focus/Disabled and
      None/Error/Warning/Success to Magento validation markup, ARIA relations and
      existing `--form-*` hooks.
    - Implement controls from the final Form Elements page. Audit the Select
      component child under `2410:14322` before defining its final semantic API;
      do not infer missing variants outside that supplied source.

### Phase E — Hyvä Custom Icon Foundation

13. Audit Launchpad Core icon library `5:28677`.
    - Inventory both `Fill Icon Sets` groups and resolve their ownership/style
      difference without relying on duplicate group names.
    - Record semantic names, style taxonomy, canonical viewBoxes and whether
      size variants are uniform scaling or optically distinct.
    - Compare component instances with library glyphs; design conflicts go to
      Designer instead of being silently substituted.
    - Completed 2026-09-23: duplicate outer labels resolve to `fill-icon` and
      `outline-icon`; representative SVG evidence confirms uniform fill scaling
      but optical outline stroke variants.

14. Establish the site-wide Figma-to-Hyvä workflow.
    - Map semantic names to
      `Hyva_Theme/web/svg/{style}/{semantic-name}.svg`; use
      `{semantic-name}-{size}.svg` for verified optical variants.
    - Use one canonical SVG per glyph/style by default; pass dimensions at usage
      through `SvgIcons::renderHtml()`.
    - Normalize monochrome vectors to `currentColor`; reject scripts, external
      references, embedded raster data and unrelated Figma frame content.
    - Keep accessibility on the containing control; decorative SVGs are hidden
      from the accessibility tree.

15. Add and validate only in-scope consumed icons.
    - Do not bulk-export the icon library.
    - Reuse a POC/theme asset only when semantic name and vector glyph both match.
    - Verify glyph, viewBox/optical alignment, explicit dimensions, inherited
      color, component states and child-theme override path.
    - Global Style currently consumes no concrete glyph, so this phase adds no
      SVG asset. Header/footer/menu/page work items will export their own subset.

### Phase F — Verification and handoff

16. Run static/deterministic gates.
    - Token audit, two clean generations + byte comparison, `npm run build`,
      `git diff --check`, generated ownership/scope review.
    - Completed 2026-09-23: audit/build/determinism/diff gates pass; hashes are
      recorded in final validation evidence.

17. Run browser validation contract.
    - Both locales, approved routes/browsers/viewports.
    - Keyboard/focus, contrast, reduced motion, reflow and third-party regression.
    - Checkout is regression-only; do not derive Form visuals from OSC.
    - Partial: Chrome desktop/runtime baseline passes. Cross-browser/device,
      English store-view and representative native-control coverage remain
      external QA and are not silently marked complete.

18. Produce evidence and update capability record.
    - Use the skill evidence structure; distinguish verified/inferred/unresolved.
    - Record deviations, screenshots, commands, output hashes and final verdict.
    - Completed 2026-09-23 via final validation summary and icon audit evidence.

## 5. Regression risks

| Risk | Severity | Mitigation |
|---|---|---|
| Replacing existing `--color-*` changes many inherited Hyvä surfaces | High | Semantic mapping matrix + representative commerce regression |
| Alias fallback resolves the wrong same-name variable | High | Require collection + exact path + one match; ambiguity is fatal |
| Generated import order overrides Hyvä unexpectedly | High | Separate ownership and inspect computed variables/build output |
| Font payload grows from normal/italic × four weights × subsets | Medium | WOFF2, measured preload, no unused duplicate external font |
| Container change affects full-width/page-builder layouts | Medium | Low-specificity wrapper contract + explicit full-bleed exceptions |
| Small Button hit areas conflict with approved accessibility baseline | Medium | Q-012 gate; no silent CSS expansion or exception |
| Large Form variant matrix creates duplicated selectors | Medium | Normalize to semantic hooks; test representative permutations rather than generating variant-specific CSS |
| Standalone Select design remains absent | Medium | Ship shared accessible native styling only; gate Select-specific visuals |
| Duplicate `Fill Icon Sets` names obscure icon ownership | Medium | Audit vectors/styles/node ownership before naming or reuse |
| Bulk icon export creates unused assets and drift | Medium | Enforce on-demand consumption and semantic path traceability |
| Local Magento bootstrap failure blocks runtime evidence | Medium | Separate technical owner restores environment; static build remains independent |

## 6. Test approach

- Transformer: CLI fixtures for parsing, aliases, collisions, modes, exclusions and
  deterministic bytes.
- CSS/build: `tokens:audit`, `tokens:generate`, double-generation comparison and
  `npm run build` under the package-required Node version.
- Browser: computed custom properties, font faces, containers, Button/Form states,
  keyboard/focus-visible, contrast, reduced motion and responsive screenshots.
- Icons: Figma instance-to-library match, SVG security/normalization, exact
  viewBox/glyph, `currentColor`, explicit dimensions and accessible-name checks.
- Regression: Homepage/CMS, customer forms, PLP/PDP/Cart; OSC checkout visual
  regression only.
- Locales: `vi_VN` and `en_US`.

## 7. Out of scope

- Header, Menu, Footer and page composition.
- Dark mode runtime or alternate child-brand implementation.
- Form variants not present in the approved Form Elements source.
- Bulk icon-library export, icons for out-of-scope components, CMS authoring,
  checkout redesign and third-party module changes.
- Repairing the unrelated VietNamAddress bootstrap defect.
