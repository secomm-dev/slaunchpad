## Summary

Thêm bảng admin-managed **status mapping** (cùng pattern warehouse map của FFC-004/PNC-004): map POS raw status code → Magento `sales_order.status`, scope theo `service_code`. Khi inbound update có **active map** → core đổi Magento order status **và** ghi comment; không map → comment only (behavior cũ). Timeline normalized vẫn do `FulfillmentStatusMapperInterface` (code) quyết, không dùng bảng này.

## Mini Spec

### Goal

Team ops kiểm soát được trạng thái Magento order hiển thị theo trạng thái POS mà không cần deploy code: admin cấu hình map "Pancake status code X → Magento status Y" trong backend, inbound applier áp dụng.

### Expected Behavior

- Core table `secomm_fulfillment_status_map`: UNIQUE `(service_code, external_status_code)`, có `is_active`, `magento_order_status`, `external_status_label` (label cache cho admin). Resolver trả active row hoặc null.
- `InboundUpdateApplier` (core): có active map → đổi Magento order status theo map + comment storefront locale; không map → comment only, không đổi status.
- Pancake admin UI (menu Secomm → Pancake POS → Status Mapping): grid + form, chỉ đọc/ghi `service_code=pancake`, catalog status từ `PancakeStatusCatalog` (kèm Magento status gợi ý: Delivered→Complete, Returned→Closed, Cancelled→Canceled…), reject trùng (service, external code).
- Log không chứa `api_key`/PII.

### Constraints / Rules

- Mapper class `PancakeStatusMapper` vẫn là nơi duy nhất chứa status code Pancake cho **timeline normalized** (epic constraint giữ nguyên); bảng map chỉ điều khiển **Magento order status**.
- Core không hard-code Pancake status; bảng + resolver vendor-agnostic, scope `service_code`.
- Không depend/sequence ShippingCore/Ghtk/Ahamove.
- Secrets không commit; PII mask trong log.
- Mode A — chạm order state transitions + DB schema → **Tier 2 review bắt buộc** trước merge.

### Out of Scope

- Timeline customer UI (FFC-003 — vẫn dùng mapper code).
- Tạo Magento Shipment/Track object.
- Map cho adapter thứ hai.

### Acceptance Criteria

- AC-001: Given map `(pancake, "3") → complete` active, When inbound Pancake status 3, Then Magento order status đổi sang `complete` + có comment
- AC-002: Given không có active map, When inbound, Then order status không đổi, chỉ comment (regression behavior cũ)
- AC-003: Given admin UI Pancake Status Mapping, When list/save/delete, Then chỉ thấy/sửa được row `service_code=pancake`; save trùng `(pancake, code)` bị reject
- AC-004: Given inbound bất kỳ, Then normalized timeline state vẫn tính từ `PancakeStatusMapper`, không phụ thuộc bảng map
- AC-005: Given log/evidence, When review, Then không có `api_key`/PII thô

## Approach

Mirror pattern warehouse map (FFC-004 core + PNC-004 UI): core owns table + resolver + repository + conflict exception; adapter owns admin UI + catalog + ACL/menu. Applier resolve map sau event-id dedup và terminal-downgrade guard, trước khi set order status trong comment history entry.
