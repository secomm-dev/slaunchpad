## Ticket + AC

[Quick Cart] Điều chỉnh UX/UI Minicart: Không nhập mã giảm giá => Click Áp dụng => Hiển thị warning message ngay phía dưới button Áp dụng: "Vui lòng nhập mã giảm giá".

- **AC-1**: submit rỗng (kể cả whitespace-only) → warning hiển thị ngay dưới button Áp dụng, không có request nào đi lên.
- **AC-2**: text theo store locale — vi "Vui lòng nhập mã giảm giá" / en "Please enter a coupon code" (BR-001: key mới ở cả 2 CSV).
- **AC-3**: luồng cũ không regressed — gõ chữ → message ẩn; mã sai vẫn ra inline error đỏ (server path); cancel coupon không bị guard chặn.

## Embedded Mini-Spec

**Hiện trạng (root cause của gap):** `initDrawerCoupon.post()` gửi `coupon_code=''` khi input rỗng → core `CouponManagement::set()` coi empty-code là no-op success → drawer chạy nhánh success, tự đóng form **im lặng**. Cart page không bị (input có `required` native tại `php-cart/coupon.phtml:111`) — gap chỉ ở drawer.

**Approach (đã duyệt trong ticket analysis):** guard thuần client-side trong template `coupon-form.phtml` (không đổi `Launchpad_QuickCart` — server-side revalidate giữ nguyên, guard là UX không phải security boundary):

1. Đầu `post()`: `!remove && !this.code.trim()` → set `error` + cờ `warning`, **return trước** `busy=true`/fetch → không POST, không đóng form.
2. Message `<p>` binding động `:class="warning ? 'warning' : 'error'"` — warning vàng (client validation, đúng chữ "warning message" trong ticket) vs error đỏ (lỗi server). Cả 2 class có sẵn trong built `styles.css` (component `messages.css`) → **không cần build Tailwind**.
3. `@input` clear `warning`/`error` → message biến mất khi user bắt đầu gõ.
4. +1 key CSV/file: "Please enter a coupon code" (vi: "Vui lòng nhập mã giảm giá", en identity).

**Tái dùng pattern sẵn của file:** `escapeJs(__('...'))` bake string server-side (như "Something went wrong..."); message `<p>` đã nằm đúng vị trí dưới button (AC vị trí không cần markup mới).
