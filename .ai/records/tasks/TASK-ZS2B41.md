## Mini Spec

### Goal

Một bộ config per-dimension dùng chung cho RATE + CREATE; merchant chỉnh qua Admin mà
không cần deploy; fix width/height bị so nhầm với length limit ở CREATE.

### Expected Behavior

- Admin: 3 field "Max Length/Width/Height (cm)" trong Sales → Delivery Methods → GHN,
  validate digits + >0, default 200.
- RATE: từng unit, dimension present + vượt limit riêng của chiều đó → ẩn GHN
  (`GHN_PACKAGE_{LENGTH,WIDTH,HEIGHT}_LIMIT_EXCEEDED`); missing dims không bao giờ reject.
- CREATE: mỗi chiều so với limit CỦA CHIỀU ĐÓ, fail-closed trước HTTP với message nêu
  đúng chiều ("package #%1 %2 is %3 cm — above the %4 cm %2 limit."); admin
  package-information block tự theo config.
- Config empty/≤0 (từng path) → fallback `GhnShipmentConstraints::MAX_SIDE_CM` (200).

### Constraints / Rules

- 3 paths shared; `MAX_SIDE_CM = 200` là constant fallback duy nhất (`RATE_MAX_SIDE_CM`
  xoá); provenance docblock ghi cả 200 (DOCUMENTED default) và 150 (SANDBOX_OBSERVED
  superseded — tuning guidance).
- `GhnPackageLimits::MAX_DIMENSION_CM` giữ làm BC default của `QuoteParcelEstimate` ctor.
- Weight limits (20/50kg) KHÔNG nằm trong scope (contract constants).
- Semantics giữ nguyên: missing dims never reject; reject carrier-owned (không fallback).
- config.xml default + const fallback phải đồng bộ khi đổi (comment ghi trong config.xml).
- STORE-scope ở RATE; CREATE đọc scope-null (giới hạn interface — DEC consequences).

### Out of Scope

- Weight limits config (follow-up nếu TL muốn); đổi reason codes; multi-carrier generic
  limits; data migration cho path cũ (giá trị cũ bị bỏ qua); store param cho
  `CarrierPhysicalLimitInterface`.

### Acceptance Criteria

- AC-001: Config getters default/fallback/override/cast (ConfigTest 3 tests, 3 paths mới).
- AC-002: RATE flow — configured limits per-dimension đi từ Config → estimator → gate
  (estimator test 110/120/130 → unit 100×130×20 violate WIDTH với limit 120).
- AC-003: CREATE — `GhnPhysicalLimit` trả giá trị config per-dimension (180/190/210);
  weight giữ contract (GhnPhysicalLimitTest 3 tests).
- AC-004: Admin 3 fields hiển thị + i18n vi/en; system.xml + config.xml đồng bộ defaults.
- AC-005: Ghn suite green + `setup:di:compile` OK + validator records baseline không tăng.
- AC-006: CREATE width/height so với OWN limit (regression tests
  GhnPhysicalParcelInterpreterTest: width 190 vs limits (200,150,200) → throw; height
  tương tự; negative control không throw) + merchant hạ config 150 → length 151 vẫn
  reject (GhnRateCalculatorTest).

## Approach

Single read seam (`Config::readPositiveIntCm`) → 3 getters shared → wiring RATE
(estimator → estimate optional param) + CREATE (GhnPhysicalLimit ctor += Config) →
per-dimension interpreter fix → system.xml + config.xml + i18n → tests → records.
