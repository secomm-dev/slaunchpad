# [SLP][TASK-N78ZEJ] MISA E-invoice Compliance Baseline (LC-31)

Generated by Secomm Production AI Toolkit

## Summary

Baseline implementation of electronic invoice (hóa đơn điện tử) issuance for Secomm
Launchpad orders via the MeInvoice Integration API (MISA): a provider-agnostic core
(`Secomm_EInvoiceCore`), the MISA/MeInvoice adapter (`Secomm_EInvoiceMisa`), and an audit
trail (`Secomm_EInvoiceLog`), plus extra-fee line promotion in `Launchpad_MageplazaExtraFeeFix`.
The implementation is staged in git (163 files, +15.3k lines) on top of `dev/development/thangpham`.

## Mini Spec

### Goal

Orders can be issued Vietnamese e-invoices (GTTGT) on MeInvoice automatically at the
configured trigger, with every attempt, payload, and provider response logged for tax
compliance — without modifying order/checkout behavior in the `Secomm_EInvoice*` modules
(they are treated as core; extensions go through pools and external plugins only).

### Expected Behavior

- Issue flow: order event (shipment/creditmemo/cancel observers) or admin button →
  `IssueInvoiceService` → provider pool → MeInvoice publish → issue log row with status,
  RefID, transaction id, invoice number, request/response payloads.
- Payload: canonical `IssueRequestInterface` carrying MeInvoice `InvoiceData` — items,
  shipping line, discount, fee/rounding (`FeeInfo`), VAT summary (`TaxRateInfo`),
  deterministic GUID `RefID` (sha256 of store + increment + revision) for idempotent
  issuance and re-issue revisions after cancel/replace.
- Adjustment invoices (ReferenceType=2) from credit memos referencing the origin
  transaction; replacement invoices (ReferenceType=1); commercial discount CKTM
  (ReferenceType=5); cancel with reason; status refresh; PDF/XML download; send-email
  to buyer.
- Totals invariant enforced by `InvoicePayloadTotalsValidator`: header totals must equal
  detail lines − discount + `FeeInfo` (tolerance 0.01); large diffs must become explicit
  lines, never FeeInfo patches.
- Admin: order-view E-Invoice tab (issue/preview/download/cancel/replace/send email/
  refresh status/CKTM), template list sync under Secomm menu, issue-log listing + view,
  ACL-protected.
- Extra fees (Mageplaza Extra Fee, e.g. "Phí bảo hiểm hàng hóa") appear as named
  `EXTRA_FEE_RULE_*` detail lines instead of the generic "Điều chỉnh" FeeInfo entry
  (`Launchpad_MageplazaExtraFeeFix` after-plugins on the MISA mappers).

### Constraints / Rules

- **Provenance**: the three `Secomm_EInvoice*` modules are ported from the company
  shared core ([TBD: source repo + version/commit], copied 2026-10-05). Local copies now
  **diverge from core**: upstream fixes do NOT flow in automatically. Re-sync policy is
  diff-confirm-then-copy (DEC-016 lesson) — never force-overwrite; local-only additions
  (the `Launchpad_MageplazaExtraFeeFix` plugins, project store config) must survive merges.
- Pre-merge check for ported code: no hardcoded endpoints/credentials from core config,
  no leftover test store ids; `db_schema_whitelist.json` matches;
  `app/etc/config.php` module state intentional.
- `Secomm_EInvoiceCore` / `Secomm_EInvoiceMisa` are project-core: no feature code written
  into them; cross-cutting behavior is added via external plugins and di.xml pool wiring.
- Order domain (CLAUDE.md): TL review required before changing order-affecting logic or
  pushing real invoices.
- `FeeInfo` is only for genuine rounding drift (< 0.01 after explicit lines); never a
  bucket for unmapped order components.
- Credit-memo adjustments only refund refundable extra fees (`rf = 1` in
  `mp_extra_fee`); non-refundable fees (e.g. insurance) never enter adjustments.
- No secrets in code/logs: MeInvoice credentials come from store config.

### Out of Scope

- Foreign-currency orders with live exchange rates (VND baseline only; conversion hooks
  exist in `SalesInvoiceContext`).
- Buyer-side portal features, invoice templates rendering customization.
- Real MeInvoice push verification (needs TL-approved sandbox run on a fresh order).

### Acceptance Criteria

- AC-001: Order issue produces a MeInvoice invoice whose payload passes
  `InvoicePayloadTotalsValidator` and whose grand total equals the Magento order total.
- AC-002: Every issue/adjustment/replace/cancel attempt is persisted in
  `secomm_einvoice_issue_log` with request + response payloads (audit).
- AC-003: Re-issue after cancel uses a new `RefID` revision; duplicate successful issues
  are idempotent (same RefID returns the existing log).
- AC-004: Credit memo triggers an adjustment invoice referencing the original
  transaction; shipping/discount/adjustment lines balance against the credit memo total.
- AC-005: Mageplaza extra fee appears as a named `EXTRA_FEE_RULE_*` line with the rule
  title; `FeeInfo` "Điều chỉnh" is absorbed (unit-tested against the real order #131
  payload fixture).
- AC-006: Admin can issue/preview/download/cancel/replace/send-email/refresh/CKTM from
  the order view tab, gated by ACL; template listing syncs from MeInvoice.
- AC-007: Unit tests cover core service (schedule, processLog, retry policy, first
  shipment gate), payload processor, extra-fee helper; `dev/tests/unit/phpunit-secomm.xml`
  green.

## Approach

Provider-agnostic core with pool seams (`IssueRequestBuilderPool`, `InvoiceIssuerPool`,
`InvoiceDocumentServicePool`, `AdjustmentRequestBuilderPool`,
`CommercialDiscountRequestBuilderPool`, `TemplateOptionsProviderPool`) and di.xml wiring
for the `misa` provider. Cross-cutting payload shaping (extra fees) lives in
`Launchpad_MageplazaExtraFeeFix` as after-plugins on the mappers, keeping the core
untouched.

## Implementation Notes

- `app/code/Secomm/EInvoiceCore/` — observers, `IssueInvoiceService` orchestration,
  lock + retry policy, admin order tab, docs (`docs/01..03`).

  reconcile cron, admin template UI.

  logger, admin listing/view.
- `app/code/Launchpad/MageplazaExtraFeeFix/` — `ExtraFeeOrderHelper::getFeeTotals()`,
  `ExtraFeeInvoicePayloadProcessor`, mapper plugins (+ unit tests; 46/46 green).
