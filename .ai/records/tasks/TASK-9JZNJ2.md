# [SLP][TASK-9JZNJ2] Fix Missing KO Dependency In MSI Source City Cascade

Generated by Secomm Production AI Toolkit

## Summary

Admin Stores → Inventory → Sources (edit): the City field renders blank and the console
throws `Uncaught (in promise) ReferenceError: ko is not defined` at
`Secomm_VietNamAddress/js/form/element/source-city.js:109` (`refreshCascade:91 →
renderLevels:104 → levels:109`). The element builds one KO view-model per schema level
(`ko.observableArray`/`ko.observable`) but its `define([...])` never declares `'ko'`. On
adminhtml, Knockout runs in AMD mode and never assigns `window.ko`, so the bare `ko`
identifier throws inside the GraphQL `.then()` — `hasSchema(true)` is already set (hiding
the native input) but `renderLevels`/`loadLevel` never run, leaving the cascade dead.
User-visible symptom reported as "region và city không load" — region is the stock MSI
`filterBy` select (verified intact: 34 VN post-2025 provinces in `directory_country_region`
× 2 locales, no mixin/preference interference); it only appears dead because the cascade
rooted on it never renders.

## Mini Spec

### Goal

`source-city.js` must resolve `ko` through the RequireJS AMD dependency list so
`renderLevels()` can build the per-level observables.

### Expected Behavior

- MSI source form, mapped country (VN): City renders the profile's level selects; level 0
  stays a disabled placeholder until `region_id` is chosen; choosing a region loads level
  options; stop-at-leaf semantics unchanged.
- Initial hydration (Edit) does not clear the saved city; a real country/region change
  still clears it.
- Unmapped country (e.g. US): fallback to the native City input (`hasSchema=false`).
- No other admin surface is affected (this is the only admin JS in `Secomm_VietNamAddress`
  or `Secomm_AddressDropdown` referencing `ko` without declaring the dependency).

### Constraints / Rules

- Change is the AMD dependency declaration only — no cascade logic edits (follows Magento
  core convention: UI form elements declare `'ko'` in `define`).
- `Secomm_VietNamAddress` is a §12 Tier-2-listed module — change flagged for TL review.
- Do not touch the uncommitted in-flight TASK-Z6SK3T working-tree files.

### Out of Scope

- Region select behaviour (stock `Magento_InventoryAdminUi/js/form/element/region` +
  `RegionSource` + `filterBy`) — no code change; re-verify on page after the fix.
- Storefront cascades (Hyvä/Alpine — no KO involved).

### Acceptance Criteria

- AC-1: Console on the source edit page shows no `ko is not defined`.
- AC-2: Country=VN + a chosen region → city/ward level select(s) load and persist on save;
  reload shows the saved value (prefill survives).
- AC-3: Country change clears the city selection and re-resolves the profile.
- AC-4: Unmapped country falls back to the native City input.
- AC-5: Validator `--check-records --check-specs` FAIL count unchanged vs baseline 56.

## Approach

Add `'ko'` to the `define` dependency array of
`app/code/Secomm/VietNamAddress/view/adminhtml/web/js/form/element/source-city.js` and bind
it as the second factory parameter (between `$` and `Abstract`), matching the
`Magento_Ui/js/form/element/*` core pattern. One-line logic change; the `ko` references in
`renderLevels()` (lines 109–111) then resolve to the injected module.

## Implementation Notes

- Root cause confirmed against the pasted console trace — frames match the current file
  exactly (`levels` = the `.map()` callback inside `renderLevels`).
- `ko` is referenced only inside `.then()` callbacks and `.map()`, so the failure surfaced
  asynchronously ("Uncaught (in promise)") and did not abort form render — which is why the
  field is silently blank instead of visibly erroring.
