# [SLP][TASK-M1J5AE] Fix Source City Cascade Never Writing Value (KO $component Binding Undefined)

Generated by Secomm Production AI Toolkit

## Summary

MSI source form: picking a ward updates the level select visually but the KO component
`value` stays empty, so the save POST carries NO `city` key at all (`region_id`/`country_id`
present) and the source saves with `city=NULL`. Headless-browser probe caught the error:

```
Unable to process binding "event: {change: $component.onLevelChange.bind($component, $index())}"
Message: $component is not defined (ReferenceError)
```

`source-city.html` (the element template of the city UI component) used `$component` inside
the `foreach: cityLevels` scope — but `$component` is only injected by Magento's `scope`
binding; element templates rendered through the UI template engine do not have it. The
`foreach` child context's `$parent` IS the city component (same as the already-working
`$parent.disabled()` in the same template). Fix: bind through `$parent`.

Also verified in the same probe round:

- Empty-city saves pass client validation and fire the POST (explains silent NULL saves).
- The "Failed to load the source-city template" console error is a first-render race in
  Magento's KO engine (the template is requested late, after the GraphQL schema resolves)
  — it stopped appearing once the foreach error stopped breaking the render cycle; no
  code change spent on it.
- Server side was never at fault: `SourceRepository` save through the full adminhtml
  plugin path (`ValidateVietNamWard`) persists city correctly (verified by direct repro
  and by the probe's post-fix save).

## Mini Spec

### Goal

Selecting a ward in the source form City cascade writes the deepest selection into the
`city` component value so the form saves `general[city]`.

### Expected Behavior

- Pick ward → `value()` = ward default_name immediately; Save persists it.
- Reload → prefill matches the saved name at level 0 (value + select show it).
- Region change still clears and reloads the cascade (untouched logic).

### Constraints / Rules

- One-line template fix only (`$component` → `$parent`); no cascade logic edits.
- `Secomm_VietNamAddress` is §12 Tier-2-listed — flagged for TL review.

### Out of Scope

- The KO engine first-render "Failed to load template" noise (no longer appears in probe;
  if it resurfaces in other admin pages it is an engine-level race, not this module).
- `levelSelected` transiently reading `undefined` right after render (cosmetic; select is
  disabled until a region is picked).

### Acceptance Criteria

- AC-1: Pick ward → `value()` equals the ward immediately (probe-verified: "An Dong").
- AC-2: Save → POST carries city; DB `inventory_source.city` = ward (probe-verified).
- AC-3: Reload → prefill selects the saved ward (probe-verified: selected="An Dong").
- AC-4: Console clean on the source edit page (probe: 0 errors after fix).

## Approach

`source-city.html`: `event: {change: $parent.onLevelChange.bind($parent, $index())}`.
Diagnosed via a headless Playwright probe driving the real admin (temp admin user,
deactivated after the probe): login → sources grid → edit Default Source → read
`uiRegistry` component state before/after picking, capture save POSTs.

## Implementation Notes

- Probe evidence: `.ai/evidence/TASK-M1J5AE/` (probe script, before/after states, payloads).
- Before the fix, both probe saves (empty + ward-picked) sent payloads WITHOUT the `city`
  key; after the fix the value reaches the provider and persists.
- Direct admin URLs need the secret key — the probe extracts keyed URLs from the menu/grid
  DOM; fieldset Address renders lazily and must be expanded before its selects exist.

## Verification

- Probe before: after-pick `value=""`, payload no city, DB NULL, 4 console errors.
- Probe after: after-pick `value="An Dong"`, save persists, reload prefills, 0 console
  errors.
- User re-test: pick ward → Save → reload shows the ward.
