# [SLP][FEAT-ZNJ4KF][TASK-08343C] Implement Launchpad Menu (Desktop mega panel + Mobile drawer)

## Mini Spec

### Goal

Implement the Desktop mega panel and Mobile/Tablet drawer from Figma page
`2949:93615` on the existing TASK-DWW34M Header, with Snowdog Menu as the
runtime data source and Hyvä UI Menu C / A-scroll as behavior baselines.

### Expected Behavior

- One managed Snowdog hierarchy (`hyva-topmenu-desktop`) feeds both renderers
  through theme-local templates; no vendor edits, no duplicate authoring.
- Desktop: full-width panel with feature (image + managed copy) and responsive
  selection-driven columns; two visible below 1440px, three visible from
  1440px, auto-scrolling rail for column 4+; hover, click/keyboard, delayed
  mouseleave, outside click, Escape, and focus restoration.
- Mobile/Tablet: A-scroll dialog drawer (logo/close/search in all states),
  root → group panel transition, single-open inline accordion, Back with focus
  restore, branch feature image, Language settings with runtime stores
  (current included, selected underline). My Account removed per user
  decision 2026-09-29.
- Header level-1 row, contextual treatments, sticky, popups and native
  fallback behave without regression.

### Constraints / Rules

- Follow SPEC-FEAT-ZNJ4KF; no `app/code/Snowdog/Menu` or vendor edits.
- Theme-local PHTML/Alpine/Tailwind v4 only; exact Figma SVG assets; both
  locale dictionaries updated.
- Node banner WYSIWYG is the primary copy source, CMS block
  `launchpad-menu-feature-<nodeId>` is the fallback; node image is the feature
  visual; nothing is hard-coded.

### Out of Scope

- Currency, socials, My Account row (user decision), footer and authentication
  logic.

### Acceptance Criteria

- [x] AC-M01 Desktop panel + drawer match the verified node contracts at
      1440/375px (geometry, typography, states); side-by-side Figma reference
      captured (screens/figma-desktop-ref.png vs impl-desktop-1440.png) —
      structure/typography/spacing match; runtime content differs by design.
- [x] AC-M02/M03 verified end-to-end with the CLI-fixture deep tree
      (columns 1/2/3, branch switch + descendant reset, category-link versus
      chevron disclosure actions, accordion
      single-open + switch, Back/Close focus restore).
- [~] AC-M04 PARTIAL: drawer search submits via button and Enter with unique IDs (verified); virtual keyboard/safe-area NOT TESTED (no tooling — manual test: open drawer on a real device, focus the search input, verify the on-screen keyboard opens, the drawer still scrolls and the close button remains reachable; safe area: verify the bottom controls clear the home indicator).
- [x] AC-M05 feature image and banner content source/fallback verified on
      desktop and mobile; mobile copy obeys its per-node flag.
- [x] AC-M06 no overflow at 320–1920px; depth policy implemented.
- [x] AC-M07 scroll restore, resize cleanup, no overlay conflicts.
- [x] AC-M09 shared hierarchy verified (one identifier, two renderers);
      Language runtime stores with current indicator; Snowdog-off fallback
      intact.
- [x] AC-M10 lint/build/validator/evidence recorded.
- [x] AC-M11 desktop level-1 inactive/current/hover/open states follow Figma
      `2151:9582`; exact current category exposes `aria-current="page"`, while

- [x] AC-M12 current/open/hover states are consistent at every rendered menu
      level: desktop nested hover/current rows use the level-1 underline and
      click-selected/open parents retain the brand-soft treatment;
      mobile root/group/accordion rows match Figma `2949:77725` with medium
      label weight and current-row `pl-2` spacing.
