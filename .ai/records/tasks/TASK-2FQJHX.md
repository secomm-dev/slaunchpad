# [SLP][TASK-2FQJHX] Remap Dangling Directory Region References After Scheme Import

Generated by Secomm Production AI Toolkit

## Summary

The VN 2025 scheme import rebuilds `directory_country_region` with new region ids but does
not remap references held elsewhere, leaving dangling region ids that break admin UIs
(vendor `region.js` throws on unknown ids — see TASK-H9ZT7G) and corrupt shipping origin
config. Audit on local dev (2026-10-02): inventory_source 1 (repaired by TASK-H9ZT7G),
customer_address_entity 2, quote_address 35, sales_order_address 13;
`shipping/origin/region_id` was dangling (repaired), `general/store_information/region_id`
had already been updated — inconsistent coverage. Needs TL/SA decision (Tier 2 — data
migration touching orders history and customer PII).

## Mini Spec

### Goal

Every active and historical `region_id` reference stays resolvable across scheme switches:
either remapped via the importer's historical snapshot mapping (old→new) or consciously
declared frozen history.

### Expected Behavior (proposal — TL/SA to decide)

- `VnAddressSchemeImporter` gains a post-sync remap step driven by the snapshot + mapping
  manifest it already maintains (old region_id → new region_id), covering:
  `inventory_source`, `core_config_data` (`shipping/origin/region_id`,
  `general/store_information/region_id`), `customer_address_entity`, and — pending TL
  decision — `quote_address` / `sales_order_address` (history immutability vs referential
  sanity for reorders/returns flows).
- Unmappable ids (region merged away with no 1:1 target) follow an explicit policy
  (NULL + keep `region` free-text), never left dangling.

### Constraints / Rules

- Tier 2 escalation mandatory (data migration, order history, PII).
- Repairs must be guarded/idempotent, run inside the importer's existing transaction phase,
  and be reported in the import result (counts + unmapped list).
- Never mutate `sales_order_address` without an explicit TL/SA sign-off recorded as a DEC.

### Out of Scope

- The one-off local-dev repair already done (TASK-H9ZT7G).
- Vendor `region.js` hardening.

### Acceptance Criteria (proposal)

- AC-1: After a pre-2025 → 2025 import on a seeded fixture, zero dangling region refs in
  the audited tables (or a reported unmapped set under an approved policy).
- AC-2: Re-import (idempotency) performs no further writes.
