# [SLP][TASK-37PS41] Fix Define/Factory Param Misalignment Breaking Admin Customer Address Cascade

Generated by Secomm Production AI Toolkit

## Summary

Admin customer address form (modal edit): the city cascade never runs — TWO "City" fields
render side by side (the server-rendered `city_select` with its caption "Please select the
city" from `Selector\City::toOptionArray`, and the native `city` input holding the saved
value). Console:

```
Uncaught TypeError: schemaCascade.createCascade is not a function
    _setupCascade provider-mixin.js:137
```

Root cause: the AMD `define` declared FOUR dependencies (`jquery`, `mage/utils/wrapper`,
`mage/validation`, `Secomm_AddressDropdown/js/form/schema-cascade`) while the factory
function took THREE parameters (`function ($, wrapper, schemaCascade)`) — the parameter
named `schemaCascade` actually received `mage/validation`; the real `schema-cascade` module
was loaded but bound to nothing. Both `mage/utils/wrapper` and `mage/validation` are unused
in the file body (dead deps left by the TASK-9EX975 Slice A refactor). The throw happens
AFTER `$root.data('secommCascadeBound', true)` is set, so any other provider instance on
the page is also blocked from binding — the cascade stays dead and both fields remain in
their server-rendered state. A deps-vs-params scan across all `web/js` files of
`Secomm_AddressDropdown`, `Secomm_VietNamAddress` and `Launchpad_Osc` found no other
affected file.

## Mini Spec

### Goal

`provider-mixin.js` binds the real `schema-cascade` module so `_setupCascade` can create
the cascade and `onSchemaResolved` can toggle the two city fields.

### Expected Behavior

- Edit address (VN): exactly ONE City field — the cascade select with vi ward options;
  saved leaf name ("Phuoc Long", a valid HCM ward of region 1205) preselects at level 0.
- Region change → cascade reloads; save + reload keeps prefill.
- Unmapped country → native `city` input fallback (`onSchemaResolved(false)` path).
- No other admin surface changes (single-file fix; scan found no sibling instances).

### Constraints / Rules

- Fix is dependency-list only — no logic edits. Dead deps are removed (preferred over
  adding the missing 4th parameter) because neither module is referenced in the body.
- `Secomm_AddressDropdown` is a §12 Tier-2-listed module — flagged for TL review.

### Out of Scope (recorded observations, TL to decide later)

- The unbounded global poll runs in EVERY `Magento_Ui/js/form/provider` instance — incl.
  `customer_form`'s own provider polling for `select[name="city_select"]` page-wide.
  Currently benign: whoever binds first sets up a working cascade, and prefill falls back
  to the input value (`currentCity = savedCity || $cityInput.val()`); still a fragility.
- `destroy()` does not clear the `secommCascadeBound` root flag (moot while insertForm
  replaces the form DOM per open, but couples to that assumption).

### Acceptance Criteria

- AC-1: Console on the customer address modal is clean (no TypeError).
- AC-2: Single City field (select) with ward options; "Phuoc Long" preselects.
- AC-3: Region change reloads the cascade; save/reload keeps prefill; unmapped country
  falls back to the native input.
- AC-4: Validator FAIL count unchanged vs baseline 56.

## Approach

Remove the two unused deps from the `define` list and the `wrapper` parameter:

```js
define([
    'jquery',
    'Secomm_AddressDropdown/js/form/schema-cascade'
], function ($, schemaCascade) {
```

## Implementation Notes

- Diagnosis chain: screenshot showed BOTH city fields in server-rendered state → the only
  code that hides either (`onSchemaResolved`) never ran → binding failed → console TypeError
  at the `createCascade` call → deps/params misalignment read directly off the file header.
- Same refactor era as the `source-city.js` missing-`ko` defect (TASK-9JZNJ2) — both shipped
  in TASK-9EX975 Slice A; the scan script (deps count vs factory params) can be re-run as a
  cheap regression check.
