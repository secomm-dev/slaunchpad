# [SLP][TASK-H9R1HX] Add carrier-internal rate fallback (TableRate/Flat Rate) when GHN/Ahamove API fails

## Summary

Follow-up of [TASK-3F6QWZ](TASK-3F6QWZ.md) (SLP-12) for Known Limitation #1: today, when the GHN/Ahamove API times out or errors in Online Mode, `collectRates()` only catches the exception and `return false` → the carrier is hidden. This task adds a **carrier-internal auto-fallback**: on API failure the carrier returns a backup rate read from the internal rate source (destination-based Mageplaza TableRate, or a per-carrier Flat Rate config) instead of hiding the method — checkout can still sell even when the carrier API is fully down.

## Mini Spec

### Goal

Remove Known Limitation #1 of TASK-3F6QWZ: the checkout flow must not depend on carrier API availability to display the GHN/Ahamove shipping methods.

### Expected Behavior

1. When a rate request to the carrier API (GHN v2 / Ahamove) throws or times out, `collectRates()` returns a fallback rate read from the internal rate source (TableRate by destination, or a per-carrier Flat Rate config) instead of `return false`.
2. The fallback rate displays a recognizable method title (e.g. suffix "(backup rate)") so both customers and operations can distinguish it from a real-time rate.
3. Fallback has a per-carrier **admin kill-switch** (default **off** — keeps current behavior until business enables it).
4. Every fallback occurrence must be logged (Logger + audit entry) so operations can detect a failing carrier API; orders placed with a fallback rate are clearly recorded in the order `shipping_description`.

### Constraints / Rules

- No changes to Mageplaza TableRate / Flat Rate core pricing logic — read results only, never modify their pipeline.
- No changes to the Mageplaza OSC checkout flow.
- Fallback rate must not be negative (>= 0) and must not apply to methods explicitly configured as strict real-time (Online Mode requiring live rates).
- Behavior with fallback **off** must be identical to today (graceful hide).

### Out of Scope

- Webhook/tracking pipeline (already standardized in TASK-3F6QWZ, DEC-TASK3F6QWZ-002).
- Order sync to the real carrier while the API is still down at order-creation time (covered by the existing GHN/Ahamove retry/queue mechanism).
- Real-time rate auto-retry inside `collectRates()` (one rate request, then fall back immediately).

### Acceptance Criteria

- AC-001: Carrier API timeout/error → GHN/Ahamove method still displays with the internal-source rate; checkout completes end-to-end.
- AC-002: Admin config toggles fallback per carrier, default off; with fallback off, behavior is identical to today (graceful hide).
- AC-003: Every fallback occurrence has a log entry; orders placed on a fallback rate are recorded in `shipping_description`.
- AC-004: No behavior change in Flat Rate / Mageplaza TableRate core (regression check on default config).

## Approach

1. Add `RateFallbackProviderInterface` (+ implementation reading TableRate/Flat Rate) to `Secomm_ShippingCore` — reuse the `OriginProviderInterface` pattern (DEC-SL015-001).
2. Wrap the API call in `collectRates()` of `AhamoveAbstractCarrier` and `GHN` with a fallback branch gated by config.
3. Admin config (system.xml) per carrier: enable, rate source (tablerate/flatrate), title suffix.
4. Mode A — mint a DEC for the fallback contract before implementation; validation L3 (checkout + carrier API, following the TASK-3F6QWZ plan template).
