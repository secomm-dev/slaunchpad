# [SLP][BUG-PWP31X] Fix VN address semantics in My Account address form — ward label + province placeholder

<!-- External ticket: SLP-152 — [My Account][My Address] Hiển thị ngữ nghĩa không hợp lý đối với địa chỉ Việt Nam (screenshotQC). -->
<!-- Generated by Claude Code per bug-record-template (Mode C). -->

## Summary

Trên form Thêm/Sửa địa chỉ My Account (`customer/address/new` + `customer/address/edit`), hai chuỗi hiển thị sai ngữ nghĩa cấp hành chính Việt Nam:

1. Dropdown **Tỉnh/Thành phố** có placeholder *"Vui lòng chọn vùng, tiểu bang hoặc tỉnh."* — bản dịch máy móc chuỗi core Magento "Please select a region, state or province."; VN không có đơn vị "vùng/tiểu bang".
2. Dropdown cấp 2 (chứa **Phường/Xã** theo mô hình hành chính 2 cấp 2025 — TASK-6MKF0V) lại mang label **"Thành phố"** — screenshot QC chú thích rõ dropdown này phải là "Phường/Xã".

## Root Cause

Form render bởi template `Secomm_AddressDropdown::hyva/address/edit.phtml` (override qua `view/frontend/layout/hyva_customer_address_form.xml`, gated `address/general/enable`). Template gọi `__('City')` và `__('Please select a region, state or province.')`. Magento merge **một dictionary toàn cục** (module dicts → theme dicts, theme thắng):

| Key | `Secomm_VietNamAddress/i18n/vi_VN.csv` (đúng semantic) | Theme `launchpad/i18n/vi_VN.csv` (stale, thắng) | Render thực tế |
|---|---|---|---|
| `City` | `Phường/Xã` (dòng 28) | `Thành phố` (dòng 360) | ❌ label "Thành phố" trên dropdown phường/xã |
| `Please select a region, state or province.` | `Vui lòng chọn Tỉnh/Thành phố.` (dòng 113) | `Vui lòng chọn vùng, tiểu bang hoặc tỉnh.` (dòng 372) | ❌ placeholder sai ngữ nghĩa |
| `Please select a city` | `Vui lòng chọn Phường/Xã` (dòng 72) | *(không có key)* | ✅ module dict thắng, render đúng |

Các value stale ở theme dict là hậu quả của đợt translate My Account trước (BUG-HE2NGV / SLP-128) — trước khi data chuyển mô hình 2 cấp (TASK-6MKF0V).

## Mini Spec

### Goal

Dropdown địa chỉ trên form My Account (và các vị trí cùng lớp lỗi trong Hyvä scope) hiển thị đúng ngữ nghĩa hành chính VN: cấp 1 = Tỉnh/Thành phố, cấp 2 = Phường/Xã.

### Expected Behavior

- vi store: label dropdown cấp 2 = **"Phường/Xã"**; placeholder dropdown Tỉnh/Thành phố = **"Vui lòng chọn Tỉnh/Thành phố."**; placeholder dropdown phường/xã giữ nguyên "Vui lòng chọn Phường/Xã".
- en store (mirror semantic, BR-001): label cấp 2 = **"Ward/Commune"**; region placeholder = **"Please select a Province/City."**
- Hành vi cascade (chọn Tỉnh → GraphQL `GetListCity` load Phường/Xã; edit-mode prefill; country-switch reset — BUG-25XDH4) **không đổi** — fix là dictionary-level, 0 dòng template/PHP.

### Non-goals

- Không đụng logic cascade Alpine/GraphQL, field names (`city`, `region_id`), DB, checkout OSC (luma-scope — theme dict dead, LL-0011).
- Không sửa template `hyva/address/edit.phtml` hay bật TASK-3T3NSV (schema-driven renderer — dormant).
- Không đổi label `State/Province` (đã đúng "Tỉnh/Thành phố").

### Acceptance Criteria

- **AC-001**: vi store — form địa chỉ My Account: label dropdown cấp 2 = "Phường/Xã" (hết "Thành phố"); placeholder "Vui lòng chọn Phường/Xã".
- **AC-002**: vi store — placeholder dropdown Tỉnh/Thành phố = "Vui lòng chọn Tỉnh/Thành phố." (hết "vùng, tiểu bang hoặc tỉnh").
- **AC-003**: en store — label cấp 2 = "Ward/Commune", region placeholder = "Please select a Province/City." (mirror, wording chờ TL duyệt).
- **AC-004**: cascade e2e regression — chọn Tỉnh → phường/xã load qua GraphQL; edit-mode prefill giữ nguyên; country-switch reset giữ nguyên.
- **AC-005**: cùng lớp lỗi đi kèm (fix cùng value key, đã sweep usage Hyvä scope): cột "City" trong sổ địa chỉ (`address/grid.phtml`) → "Phường/Xã"; region placeholder ở `form/register.phtml` + `php-cart/shipping.phtml` (cart estimate) → wording mới đúng ngữ nghĩa; checkout OSC không đổi.
- **AC-006**: change set = 2 file CSV (`vi_VN.csv` + `en_US.csv`, mirror BR-001), không file PHP/template nào.

## Approach

Dict-only — sửa **value** của 2 shared key ở theme dict thay vì đổi key trong template:

- Sửa value (không thêm key mới) vì mọi usage Hyvä scope của cả 2 key đều là ngữ cảnh địa chỉ VN (sweep: `address/grid.phtml`, `form/register.phtml`, `php-cart/shipping.phtml`, template edit.phtml của AddressDropdown; template vendor `Magento_Customer/address/edit.phtml` dead — đã bị override; `schema-edit.phtml` dormant sau config flag) → wording mới đúng ngữ nghĩa ở TẤT CẢ các vị trí đó.
- Ưu điểm so với đổi key template (`Ward/Commune`): không thêm key song song, fix luôn cột grid sổ địa chỉ (nếu chỉ sửa template thì grid phải override vendor riêng = scope lớn hơn), template cascade giữ nguyên byte-for-byte.
- Checkout OSC không lộ: luma-scope dùng module dict `Launchpad_MageplazaTranslate` (LL-0011), theme dict dead.
- Wording VI mirror `Secomm_VietNamAddress/i18n/vi_VN.csv` (dòng 28 + 113) — wording đã tồn tại trong hệ thống; EN mirror semantic ("Ward/Commune" từ module en_US dòng 115; "Please select a Province/City." là source key module vi dòng 121).
