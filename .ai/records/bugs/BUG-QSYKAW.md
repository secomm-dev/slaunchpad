# [SLP][BUG-QSYKAW] MoMo return success page depends on checkout session Last* keys (paid customer bounced to cart)

## Summary

MoMo (`Secomm_MoMo`, order-first flow) trả khách về `momo/payment/returnaction`
với `resultCode = 0`, nhưng `ReturnAction` chỉ đọc `resultCode` rồi redirect
`checkout/onepage/success` — nó không xây lại session. Success page chuẩn
(Magento `SuccessValidator`) yêu cầu session còn đủ
`LastSuccessQuoteId`/`LastQuoteId`/`LastOrderId`. Khi MoMo redirect về với
session mới/mất (return trùng lặp, cookie mất, session expired), validator
fail và khách **đã trả tiền** bị đá về `checkout/cart`. Cùng lớp lỗi với
Blocker 2 của ZaloPay (FEAT-ZLP1PF §11.2).

## Mini Spec

### Goal

`resultCode = 0` return phải đưa khách tới một success page hợp lệ kể cả khi
checkout session trống, bằng cách resolve order từ chính dữ liệu MoMo gửi về.

### Expected Behavior

- `resultCode = 0`: order được resolve theo `orderId` param MoMo echo (= increment
  id; fallback session `getLastRealOrderId()`), verify là order MoMo
  (`ConfigProvider::CODE` = `momo_payment`), rồi `clearHelperData()` + rebuild
  đủ 5 key session (`LastQuoteId`, `LastSuccessQuoteId`, `LastOrderId`,
  `LastRealOrderId`, `LastOrderStatus`) — mirror core `Onepage::saveOrder` /
  `QuoteManagement`.
- Order không resolve được / không phải MoMo order: message customer-safe + cart
  redirect — không bao giờ success page rỗng.
- `resultCode != 0`: giữ nguyên hành vi lenient cũ (cart + message, không lookup,
  không đụng session) — Notify (IPN) vẫn là nguồn authoritative duy nhất.

### Constraints / Rules

- Không thay đổi Notify/NotifyValidator/TransactionHandler (đã idempotent +
  verify signature/amount/extraData đầy đủ — đã rà, không cần sửa).
- Không đặt order, không invoice, không đổi order state trong return flow.
- Session keys chỉ được viết ở MỘT nơi duy nhất (`ReturnProcessor::prepareSuccessSession`).

### Out of Scope

- Mageplaza OSC rendering, refund subsystem, MoMo API contract.

### Acceptance Criteria

- AC-001: `resultCode=0` + `orderId` param → 5 session key được rebuild từ order
  resolve được, path = success.
- AC-002: `resultCode=0`, thiếu `orderId` param → fallback session id, vẫn rebuild.
- AC-003: order không tồn tại / payment method khác → LocalizedException
  customer-safe, KHÔNG session write.
- AC-004: `resultCode!=0` → cart, không lookup, không session write.

## Steps to Reproduce

1. Thanh toán MoMo thành công (IPN tạo invoice, order `processing`).
2. Browser trở về return URL trong context session mới/mất (cookie bị xóa,
   duplicate return sau khi success page đã `clearQuote`, session expired).
3. `ReturnAction` thấy `resultCode=0` → redirect success page.
4. `SuccessValidator::isValid()` fail (thiếu Last* keys) → `Onepage::Success`
   redirect `checkout/cart`.

(Bug xác định bằng code-path trace đối chiếu core `SuccessValidator`/`Session`;
chưa có bản ghi reproduction runtime — xem §Verification.)

## Root Cause

`ReturnAction::execute()` (2.0.0) chỉ đọc `resultCode` và redirect — không
resolve order, không rebuild session keys. Order-first flow đặt order trước khi
redirect nên session keys tồn tại trong happy path, nhưng return URL là GET
stateless từ MoMo: mọi trường hợp session không còn keys đều fail validator.

## Fix

- NEW `Service/ReturnProcessor.php`: `process(array $params): string` — logic
  resolve order (SearchCriteria `increment_id`) + validate payment method +
  rebuild session (single writer). Non-zero resultCode short-circuit cart.
- `Controller/Payment/ReturnAction.php`: delegate sang `ReturnProcessor`; catch
  `LocalizedException` → error message + cart.
- Unit tests: `ReturnProcessorTest` (6: 4 AC + session-fallback + skip-path),
  `ReturnActionTest` (3), `SessionStub` (session stand-in record mọi write —
  magic `__call` không mock được trên PHPUnit 10).
- `CHANGELOG.md` 2.0.1 + `README.md` bullet Return cập nhật.
