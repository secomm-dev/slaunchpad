# [SLP][BUG-11997Y] [COD Risk] COD availability plugin never executes — wrong target FQCN

<!-- Found during TASK-YPWH9B self-test round 1 (2026-09-22). User-confirmed fixed 2026-09-29 (checkout COD hidden). -->

## Mini Spec

### Goal

Plugin availability phải thực thi trên đúng class COD của core để BLOCK ẩn COD ở checkout; khách bị chặn không thể đặt đơn COD bằng bất kỳ đường dẫn nào.

### Expected Behavior

- `Magento\OfflinePayments\Model\Cashondelivery::isAvailable()` đi qua plugin `Secomm\CodRisk\Plugin\CashOnDeliveryAvailabilityPlugin` (interceptor).
- BLOCK → COD ẩn ở payment list; fail-open khi evaluator lỗi (log critical).

### Constraints / Rules

- FQCN target phải lấy từ vendor — `vendor/magento/module-offline-payments/Model/Cashondelivery.php` (chữ "d" thường, xác nhận qua `etc/config.xml` core dòng 37). Không viết theo trí nhớ.
- Chỉ after-plugin; kill-switch `codrisk/general/enabled`.

### Out of Scope

OSC payment-list reload UX (xử lý riêng trong TASK-YPWH9B — telephone-sync JS + place-order gate).

### Acceptance Criteria

- AC-01: `php var/codrisk_probe.php` (đã xóa) cho thấy plugin trong interception config của `Cashondelivery` và factory tạo `\Interceptor`.
- AC-02: Checkout với phone blacklist → COD ẩn + log `[CodRisk] COD hidden for phone ...`; payment khác không đổi.
- AC-03: enabled=No → hành vi gốc.

## Root Cause

FQCN target ghi sai từ trí nhớ (`CashOnDelivery`) — class thật là `Cashondelivery`. Plugin gắn vào type không tồn tại → không bao giờ được gọi; phát hiện qua runtime probe khi mọi tầng tĩnh đều "đúng".

## Fix

- `etc/di.xml`: type name → `Magento\OfflinePayments\Model\Cashondelivery`.
- Plugin: type-hint `$subject` → `Cashondelivery`.
- Follow-up cùng bug report: (1) **place-order gate** — observer `sales_model_service_quote_submit_before` (`CodAvailabilityGuard`) từ chối đặt đơn COD khi BLOCK (OSC không reload payment list theo phone edit → list stale; server-side là chốt chặn cuối, fail-open nhất quán); (2) **telephone-sync JS** — debounce 600ms → core action `set-shipping-information` để list tự reload khi chỉ đổi phone (không mixin nội bộ OSC).

## Verification

- AC-01/02/03: PASS (user-verified 2026-09-29 — COD ẩn khi blacklist, hiện lại khi gỡ).
- Regression: payment khác đặt đơn bình thường (PASS).
