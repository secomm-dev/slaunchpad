# Decision Record: VNPAY status mapping

## Context

Current IPN only checks `vnp_ResponseCode == '00'` and auto-cancels everything else. VNPAY also sends `vnp_TransactionStatus`; code 07 = success-but-suspect-fraud. Auto-cancel/processing on incomplete mapping risks revenue loss or fraud exposure. Payment-state-transition + data-integrity category.

## Decision (open — SA/TL + PM)

Map **both** `vnp_ResponseCode` and `vnp_TransactionStatus` to Magento states per a documented table:
- success (00/00) → STATE_PROCESSING + invoice + payment transaction
- suspect (07) → PAYMENT_REVIEW / HOLD (manual review, **not** auto-process/cancel)
- failure (others) → STATE_CANCELED + comment + audit
Table to be finalized with SA.

## Alternatives

- Keep ResponseCode-only (loses suspect handling — rejected).
- Auto-cancel on 07 (fraud risk — rejected).

## Consequences

Prevents auto-settling fraudulent payments and lost valid ones; requires SA to ratify the exact code→state table.

## Affected components

`Vnpayment_VNPAY/Controller/Order/Ipn.php` (status branch); payment model.
