# Decision Record: Per-shipping-method VN customization → Launchpad (project, per-carrier, optional)

<!-- CANONICAL DECISION STORE (Phase 1a / RM-01). Accepted via user acting as SA/TL (chat 2026-07-29). -->

<!-- Refines DEC-017 scope: module = generic address only; per-carrier = Launchpad. -->

## Context

[FEAT-005](../features/FEAT-005.md) (VN shipping address support) cần customize shipping methods cho VN. Nhưng shipping methods là **mix**: vừa **3rd-party** (`Mageplaza_TableRateShipping`, future GHN, Ahamove) vừa **Secomm**. **Không thể ép mọi carrier** phải extend một rule/contract chung (carrier 3rd-party không kiểm soát được; ownership lẫn lộn).

Câu hỏi: phần customize per-carrier cho VN đặt ở đâu? DEC-017 đã chốt phần **generic** (data + cart estimate cascade) → `Secomm_VietNamAddress` (module). Phần **per-carrier** cần quyết định riêng.

Tier-2 (shipping — §12) → Level-2 architecture decision, SA/TL.

## Decision

**Mỗi shipping method có phần customize VN riêng, nằm trong package Launchpad** (project layer: `app/design/frontend/Secomm/launchpad/` + project `app/code`), **KHÔNG** thuộc module `Secomm_VietNamAddress`.

- **Tính chất:** per-carrier, **individual + optional** — mỗi carrier customize riêng, chỉ khi project dùng carrier đó. **Không có rule/contract chung bắt buộc** mọi carrier extend.
- **Module `VietNamAddress`** chỉ expose **generic** VN address capability (data + GraphQL reuse + cart estimate cascade — DEC-017). Launchpad **wire** per-carrier vào capability đó.
- **DEC-8 (reusability boundary):** module giữ carrier-agnostic/reusable; carrier-specific glue (3rd-party hoặc Secomm) → project (Launchpad). Giống cách OSC coupling → Launchpad (SL-002/DEC-8).

Approved via user acting as SA/TL authority (chat 2026-07-29). Formal SA/TL name [TBD].

## Alternatives

- **Bắt mọi carrier extend một interface VN chung trong module:** rejected — carrier 3rd-party không ép được; ownership lẫn lộn (3rd-party + Secomm).
- **Per-carrier customization trong module `VietNamAddress`:** rejected — module phụ thuộc carrier 3rd-party cụ thể → mất reusable (vi phạm DEC-8).
- **Per-carrier trong `Secomm_AddressDropdown`:** rejected — double vi phạm DEC-8 (generic + carrier-coupling).

## Consequences

- (+) Module `VietNamAddress` giữ reusable, carrier-agnostic; Launchpad sở hữu glue carrier-specific (DEC-8).
- (+) Mỗi carrier customize chỉ khi dùng — không over-engineer cho carrier không có.
- (−) "VN shipping completeness" phụ thuộc Launchpad wire **từng** carrier → TableRate trước (SL-004); GHN/Ahamove cần ticket riêng khi cài (SL-005/006).
- (−) Nếu add carrier mới, phải tạo customization VN trong Launchpad (không tự động).

## Affected components

Launchpad package (`app/design/frontend/Secomm/launchpad/` + project `app/code`); per-carrier: `Mageplaza_TableRateShipping` (SL-004 now); GHN/Ahamove (SL-005/006, future). Module `Secomm_VietNamAddress` **không** chứa carrier logic.
