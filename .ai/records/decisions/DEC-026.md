# Decision Record: Work-Item Identity Model (P2A)

## Context

Ticket IDs của project này theo mô hình `<abbrev>-<sequential>` (`SL-001`…`SL-025`), cấp phát ad-hoc bằng cách nhìn số lớn nhất hiện có +1. Khi nhiều developer / AI agent / branch / workspace phân tích và tạo work item song song, các bên độc lập tính cùng số kế tiếp → trùng ID khi merge (chính là race mà Entry h đã xử lý cho DEC files, nhưng work-item IDs thì chưa có cơ chế). Đồng thời domain model trộn lẫn: identity, project namespace, Feature→ticket membership, display naming và external PM IDs không tách rời.

Audit còn phát hiện: tiền tố `SL` bị hard-code literal trong validator regex của toolkit (`^(FEAT|SL|BUG|REL)-[0-9]{3,}$`) — không có per-project config, không có TASK/SPIKE type, không có trường external PM refs.

## Decision (accepted)

1. **Adopt P2A identity model** cho slaunchpad (đồng bộ toolkit-first; canonical rule `.ai/rules/work-item-identity.md`):
   - Work item MỚI mint ID collision-safe `<TYPE>-<6 ký tự Crockford Base32>` (loại I/L/O/U) bằng `.ai/bin/project-ai-idgen` — KHÔNG max+1, an toàn concurrent.
   - Project Code = `SLP`, SSOT `.ai/toolkit/project.yaml` (bootstrap detect `SL` unambiguous → TL chuẩn hóa `SL→SLP` qua workflow; đổi code KHÔNG regenerate IDs).
   - TASK/SPIKE records mới: `.ai/records/{tasks,spikes}/`; membership Feature = frontmatter `parent` (mutable); KHÔNG auto-tạo Feature một-ticket.
   - Display title `[SLP][FEAT-…][TASK-…] <Title>` render từ metadata (H1); validator `--check-identity` FAIL khi stale; metadata authoritative.
   - External PM IDs (XCorp/Jira) → `external_refs`, never canonical; alias lịch sử → `legacy_ids` (mỗi legacy ID một owner duy nhất).
2. **Grandfather toàn bộ item hiện tại** (class A/B per §10): `SL-001..025`, `FEAT-001..008`, DEC/SPEC files giữ nguyên identity + filename; dual-format regexes giữ mọi tham chiếu cũ resolve; KHÔNG bulk rename. Item mới dùng model mới ngay lập tức.
3. Spec naming nối dài: `SPEC-<ITEM-ID>-<slug>.md` chấp nhận owner mới (`SPEC-TASK-4P8DX2-…`) — mở rộng DEC-SL019-001, không thay thế.

## Alternatives

- **Tiếp tục SL-NNN + lock file:** reject — không xử lý được multi-branch/multi-workspace (lock cục bộ không chặn nhánh khác), vẫn trùng khi merge.
- **Re-mint toàn bộ 25 tickets + rewrite references (FEAT-006 nằm trong 30 files):** reject — destructively churn history/PM references trái chính sách migration §10; grandfather + alias đủ traceability.
- **Counter prefix khác (FEAT-001/TASK-001 tuần tự):** reject — vẫn là sequential, cùng bài toán collision.

## Consequences

- Tích cực: tạo work item song song không cần phối hợp; đổi project code / re-parent / đổi title không đụng ID; PM-tool adapters (Feature→Epic, Task→Ticket) không đổi core identity; tiêu đề PM-tool tự cho biết project/feature/ticket.
- Tiêu cực (chấp nhận): hai format ID song hành (legacy + mới) — giảm dần theo thời gian vì chỉ item mới dùng format mới; ID mới không gợim số thứ tự/thời gian (không sortable) — chấp nhận đổi lấy collision-safety.
- Follow-up obligations: agent rule — mọi ticket/task/bug/spike record mới PHẢI qua idgen + `--check-identity` trong validate thường xuyên; DEC files của work-item mới sẽ mang prefix dài hơn (`DEC-TASK4P8DX2-001`).
