# Decision Record: Toolkit Phase-1 retrofit sync (batch 2026-07-22)

## Context

slaunchpad was generated 2026-07-14 and last synced at CHANGELOG 1.2.0 (2026-07-16). The toolkit received a Phase-1 retrofit/upgrade batch on 2026-07-22 (registry, validator, upgrade engine, migration framework P1A–P1F, drifted skills) that had **not** been propagated. Dry-run `bin/project-ai-upgrade` reported the project behind current: 5 templates missing, 4 contract files outdated, migration markers unstamped, 5 non-nav skills drifted, 2 runtime guides missing. The validator still read `VALID` only because the *minimum* contract held — the Phase-1 `--check-*` modes did not yet exist in the project's binary.

## Decision

1. **Run the upgrade engine** `bin/project-ai-upgrade --project …/slaunchpad --apply --force` to bring contract files + templates + migration markers to the 2026-07-22 baseline (idempotent, ownership-aware).
2. **Force-overwrite the 4 outdated contract files** (validator, registry, decision-record + feature-record templates). Diff confirmed the local versions are *older toolkit versions*, not project customizations — purely additive toolkit improvements (6 new `--check-*` modes, `phase1_capabilities` block, B1 record fields + `decision_approval_summary`). No local-only content lost.
3. **Manually sync the 5 drifted non-nav skills + 2 runtime guides** — these sit outside the engine's sync manifest (the engine deliberately preserves non-nav skills as user-extension), so they require diff-confirm-then-copy. Diff confirmed additive-only.
4. **Do NOT copy `bin/run-contract-tests` into the project** — verified it is toolkit-workspace-only: it resolves `ROOT` relative to its own path and requires `$ROOT/shared-core/registry/` (toolkit layout); the project layout (`.ai/registry/`) makes it fail (6/26 pass when run from `.ai/bin/`, 25/25 from the toolkit). Project contract is covered by `project-ai-validate` + `project-ai-upgrade` dry-run.
5. **Do NOT modify `AGENTS.md`** (shared-owned). Semantic P1B (per-work-item mode, §9) / P1E (context quota, §8.6) / P1F (governance dedup, single-source + `no-duplicate-knowledge` rule) are already satisfied — only the markers were missing. No AGENTS.md merge needed.
6. Scope = full Tier 1 + Tier 2 (user-approved); the only deviation from the literal Tier-2 list is omitting `run-contract-tests` (see #4 — toolkit-only).

## Alternatives

- **Tier 1 only (engine, no manual skill/guide sync):** rejected — leaves the substantive `magento-module-analysis` 19-line analysis gap + Phase-1a skill notes unaddressed; user chose full sync.
- **Re-generate from scratch:** rejected — would discard project-owned records/decisions/state + the Phase-1a canonical records in active use (FEAT-001..004, DEC-010..015); engine upgrade is the sanctioned in-place path.
- **Keep local contract files (no `--force`):** rejected — local versions are merely older; keeping them leaves the project unable to run the 6 Phase-1 validator checks.

## Consequences

- Project now reads as Phase-1-applied (`applied_migrations: [P1A..P1F]`); re-running the engine is a no-op (IN SYNC).
- `.ai/` + `.claude/` remain untracked in git — TL must review the on-disk diff and commit (backup at `.ai/toolkit/_pre-sync-backup-2026-07-23/` is the rollback path).
- No change to any Hard-Gate area (payment/checkout/shipping/order/customer/PII/DB/security/deploy) — AI-tooling layer only.

## Affected components

`.ai/bin/project-ai-validate`; `.ai/registry/toolkit-capability-registry.yaml`; `.ai/templates/*`; `.ai/toolkit/toolkit-version.md`; `.ai/{workflow,initialization}/*_RUNTIME_GUIDE.md`; `.claude/skills/{spec,task,testcase,review-code,magento-module-analysis}/SKILL.md`. (`bin/run-contract-tests` intentionally NOT copied — toolkit-only.)
