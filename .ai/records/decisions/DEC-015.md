# Decision Record: VNPAY payload contract versioning

## Context

Requirement states the external provider payload contract **may need to change**. Current IPN parses a fixed param set; a VNPAY v2 payload (new/renamed fields) would break parsing silently. External-API-contract category.

## Decision (open — SA)

Document the expected payload schema; parse defensively (ignore unknown optional fields; **fail safe** on unknown **mandatory** fields → reject + audit); version-detect if VNPAY exposes a version/shape signal; gate behaviour on contract version.

## Alternatives

- Strict current-only parsing (breaks on contract change — rejected).
- Accept anything (masks real malformed callbacks — rejected).

## Consequences

Robust to provider evolution; requires a documented schema + SA signoff on fail-safe semantics.

## Affected components

`Ipn.php` (param parsing); payload schema doc.
