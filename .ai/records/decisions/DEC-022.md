## Context

FEAT-006 hiện có hai assumption mỏng về con số giao dịch với GHTK:

1. **Weight:** giả định "Magento `weight` luôn là kg → ×1000 = gram". Audit (2026-07-30) cho thấy: **không có weight-unit config nào** trong project; `Mageplaza_TableRateShipping` đọc raw `weight` attribute (`config.xml`: `volume_weight=weight`, `weight_attribute=weight`) không giả định đơn vị. Magento `weight` attribute là **unitless** → giả định "kg" chưa được verify.
2. **Rate composition:** FEAT-006 chỉ nói "response `fee.fee`" mà không xác định shipping amount trả về Magento gồm trường nào (có inkl. `insurance_fee`? `extFees`? `delivery`?). Bỏ ngầm insurance/surcharge = merchant chịu chi phí sai.

GHTK fee API response tối thiểu có: `fee.fee`, `fee.insurance_fee`, `fee.extFees`, `fee.delivery`. Cần policy rõ cho cả đầu vào (weight) và đầu ra (amount).

Tier-2 (shipping carrier + API contract + pricing — §12) → Level-2 contract/business decision, SA/TL.

## Decision (accepted 2026-07-30 — user as SA/TL)

### Part A — `ShipmentWeightCalculator` contract

1. Tạo responsibility riêng `ShipmentWeightCalculator` (không nhét vào carrier).
2. **Chỉ tính shippable items**; loại virtual/downloadable items; xử lý qty.
3. Xử lý configurable (parent/child — không double-count) + bundle theo Magento weight semantics.
4. Xử lý item/product **thiếu weight** (missing/0) → áp dụng minimum/default weight từ admin config.
5. **Đọc weight unit/configuration của project** (config field `weight_unit`, default đề xuất `kg`) → **normalize sang gram** cho fee API. KHÔNG hard-assume kg.
6. **Rounding rule rõ** (đề xuất: `ceil` lên gram nguyên).
7. **Order API dùng cùng unit weight (gram)** như fee API (Q2 resolved 2026-07-30). Vẫn tách DTO fee vs order để cô lập field contract, nhưng cùng unit → `ShipmentWeightCalculator` dùng chung cho cả hai (SL-009 cho SL-010 reuse).

### Part B — fee-response rate composition

8. Parse + persist tối thiểu `fee.fee`, `fee.insurance_fee`, `fee.extFees`, `fee.delivery` (encapsulate trong **response mapper** — nếu response contract thực tế khác doc thì sửa mapper, không rải logic).
9. **Rule:** nếu `fee.delivery` không cho phép giao → **không trả shipping method** (không rate).
10. **Không âm thầm bỏ** insurance hoặc surcharge.
11. **Displayed shipping amount = config-driven multi-select "include" (Q1 resolved 2026-07-30):** base `fee.fee` **luôn** included; admin có multi-select **"include"** gồm `insurance_fee` và `extFees` → merchant chọn thêm trường nào cộng vào displayed amount. Default đề xuất: chỉ `fee.fee` (không include gì thêm) — merchant bật qua config.
12. Lưu breakdown đầy đủ (`fee.fee`/`insurance_fee`/`extFees`/`delivery`) vào debug log đã mask bất kể config include. Test order value cao + insurance/surcharge.

## Alternatives

- **Giữ assumption "weight = kg":** rejected — unitless attribute, chưa verify; sai unit = sai phí.
- **Chỉ dùng `fee.fee`, bỏ insurance/surcharge:** rejected — merchant chịu chi phí sai; âm thầm bỏ = bug tài chính.

## Consequences

- (+) Weight chính xác theo unit config; rate composition minh bạch; merchant không âm thầm chịu phí.
- (+) Response mapper cô lập doc drift; breakdown log hỗ trợ reconcile.
- (+) Rate composition config-driven → SL-009 unblocked (→ ready).
- (−) Thêm `ShipmentWeightCalculator` + response mapper + admin `weight_unit`/`min_weight`/`include` multi-select config.
